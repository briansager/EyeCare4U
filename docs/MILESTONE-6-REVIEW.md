## Audit and concrete changes

| Area audited | Finding and disposition |
| --- | --- |
| Normal/snooze/break/blockers | Existing monotonic/credited clocks, explicit Start, manual Pause precedence, at-most-once occurrence effects and interruption-before-completion are retained. Existing deterministic regressions continue passing; no speculative timer rewrite. |
| Storage initialization | Confirmed defect: a successful preferences load followed by failed history query returned defaults, which a later checkpoint could save over valid choices. Return the loaded validated preferences even if history cannot load. New regression exercises the exact failure. |
| Background tasks | Confirmed unobserved-task path: a preferences-provider exception before the service call faulted a discarded checkpoint task. HistoryViewModel now owns/reports that failure, resets busy state, allows retry, and announces only health transitions. SQLite remains on its existing FIFO worker. |
| Startup / close / dispatch | Async startup now has a visible safe failure message and cleanup/exit rather than an unhandled async-void exception or silently exiting on mutex failure. Final checkpoint awaits are contained, always complete the close path, and warn if recent data could not save. Cross-thread session delivery is posted to the dispatcher and ignored after closing begins. Normal Close was checked on the portable app; tray Exit shares that path but remains a native tray check. No blanket continue-after-crash handler was added. |
| Notification/sound failure | Existing Core Effect containment and once-per-occurrence guards are retained. Native PlaySound stop failure now throws into that existing status path; Dispose marks itself disposed even if Stop fails. Audible output/real shell delivery remain unverified. |
| Shutdown/subscriptions | Existing idempotent monitoring/tray disposal and awaited final flush retained; high-contrast/static and history/view-model handlers detach on Closed. Published Close left no process. OS termination may bypass flush; no forensic/guaranteed cleanup claim. |
| SQLite/version/epoch | Transactional schema 1, parameters, foreign keys, cumulative stable IDs, serialized writes, generation guards and clear epochs retained. Corrupt/newer schemas remain preserved. Another confirmed failure path was a malformed event offset reaching UI date formatting and aborting startup; event kind/offset/date-range invariants are now checked inside the storage failure boundary. Real temporary-DB regressions preserve invalid rows byte-for-byte while retaining valid preferences and reporting unavailable history. Populated isolated Clear regression now crosses confirmation commands, live session/timer, queued/stale batches, subsequent collection and restart. |
| Single instance / isolated data | Same per-user Windows mutex remains before DB/monitoring. Second published launch exited. Normal LocalApplicationData path unchanged. Explicit --isolated-review accepts only marked temporary GUID children, rejects ordinary/unmarked paths and reparse-point directories, and labels the title. No review controls were added to the normal UI. |
| Dates | Today/event display now uses invariant Gregorian formatting plus each event's recorded offset, consistent with stored date keys even under th-TH calendar culture. New regression verifies both. |
| Accessibility | Hard-coded-only colors could ignore high contrast; dynamic palette now switches to system Window/WindowText brushes and observes changes. Visible keyboard focus added. History access keys, human-readable row names, one Tab stop per grid with arrow navigation, and disabled column reordering/sorting keep navigation stable. Clear defaults focus to Keep; Escape cancels; cancellation/completion return focus to Clear. Periodic snapshots do not move focus or generate per-second announcements. |

No persistent diagnostics/logs or raw exception messages/activity are written. Recoverable storage/notification/sound failures have bounded user-facing status. Startup and final-save failures use concise dialogs. Expected storage failures remain nonfatal while timing is in memory. Unexpected fatal programming/platform failures are not universally swallowed; this is not proof of crash-free operation. There are no application animations or motion effects to disable; native controls keep platform behavior.

## Packaging and automated validation

Version: **0.6.0-rc.1**, introduced in Directory.Build.props because no prior release-version convention existed. Run:

```powershell
pwsh -NoProfile -File scripts/Package-Portable.ps1
```

The script runs locked restore; Release build; all tests; direct/transitive advisory check; locked self-contained win-x64 restore/publish; required notices; a per-file manifest; normalized ordered ZIP entries/timestamps; external SHA-256; positive verification and three negative verifier regressions. It uses ordinary multi-file publish with trimming, Native AOT and single-file modes explicitly off. Build/test tools, owner data, databases/sidecars, logs, secrets, debug symbols and source build directories are excluded/rejected. A new staging directory is used each time; only the exact generated versioned ZIP is replaced, without recursive deletion. Build products and synthetic tamper tests stay under ignored artifacts/. The normal app's user data remains in LocalApplicationData.

Output: `artifacts/packages/EyeCare4U-0.6.0-rc.1-win-x64.zip` and `.zip.sha256`; 492 archive files in the qualified package. The manifest records version, SDK/runtime, win-x64/self-contained flags, source commit, dirty status and every other file's hash. A package from a dirty tree is labelled accordingly; final handoff gives the checksum rebuilt at the published commit. Package-owned text is normalized to LF/UTF-8 independently of checkout line endings; upstream notices remain byte-for-byte. ZIP bytes depend on exact source, toolchain and locked inputs; normalized packaging does not promise identical bytes across arbitrary SDK/PowerShell/compression implementations.

Final qualification: restore/build succeed, **0 warnings/errors; 187 tests passed, 0 failed, 0 skipped** (139 Core, 32 App, 16 Storage). All original 179 remain. Added tests cover preference preservation on query failure, checkpoint failure ownership/health announcements/recovery, populated isolated confirmation/clear/live-timer/new collection/restart, isolated-path safety, Gregorian recorded-offset display, and malformed stored-event preservation. The separate packaging regressions reject wrong outer checksums, altered manifest content and an injected synthetic history.db. No owner history was used for destructive tests.

Development packaging failures were investigated and corrected: mismatched runtime lock graphs; a file-filter false positive on the SQLite license filename; and setting ZIP timestamps after an entry had already been written. Staged review also caught the existing database glob hiding the required Microsoft.Data.Sqlite license; an exact tracked-file exception fixes clean checkouts. Final script/verification passed after these corrections. No failing iteration is counted as qualification evidence.

CI runs the same script then uploads ZIP/checksum using the [official upload-artifact v7 interface](https://github.com/actions/upload-artifact), with contents:read only, no deployment secrets and 14-day retention. Upload is a workflow artifact, not a GitHub Release/tag. Hosted result and final commit/checksum are reported in the handoff.
